## 三、 Mark 老師親授：找不同「黃金開發規範與實戰心法」

歷經多次深入探討與實戰打磨，後續所有找不同出圖與改版**必須嚴格遵守以下各大鐵律**：

### 鐵律 0：單字候選五級金字塔標準與覆蓋原則（核心教學綱領）

找不同遊戲的目標單字絕非憑空捏造或隨意選取，必須嚴格依照以下**五級優先權金字塔**進行篩選與配置：

1. **第 1 優先（核心中的核心）**：各冊 **Unit 1, 2, 3, 4 的單元主要學習單字**。
2. **第 2 優先（官方延伸單元）**：各冊 **Starter 單元與 Festival（節慶）單元單字**（如 Mother's Day, Halloween, Christmas 等）。
3. **第 3 優先（自然拼讀具象字）**：課本 **Phonics（語音拼讀單元）** 裡提到的具象名詞（如 `pot`, `top`, `bed`, `pet`, `pig` 等）。
4. **第 4 優先（國小基本課綱字）**：**教育部國小 300 字**。
5. **第 5 優先（權威能力指標）**：**小學英檢 (GEPT Kids) 官方字表**（由 LTTC 財團法人語言訓練測驗中心提供之小學英檢參考字表，共收錄約 685 個最適合小學生的單字）。

> [!IMPORTANT]
> **【出題覆蓋率黃金準則】**：
> - 找不同遊戲**必須以「第 1 級」與「第 2 級」為主，且務必全面涵蓋覆蓋！**
> - 可以的話**再加「第 3 級」（Phonics 具象名詞）**，接著**再來加入「第 4 級」（教育部國小 300 字）**。
> - 絕不允許使用跨冊超綱或非課綱單字取代當冊主單元的核心單字！

### 鐵律 1：構圖情境化與合理性（整幅畫作概念）
1. **拒絕人工擺拍感**：
   - 絕不能整幅圖只有 8 個目標物件，好像專門為出題而硬畫上去。
   - 絕不能把 3～4 個目標單字硬塞在同一張桌子或同一個角落。
2. **豐富的「非目標靜態裝飾物」（干擾項）**：
   - 畫面必須融入大量已學過或生活常見的自然配飾（例如石階、拱門、吊燈、藤蔓、盆栽、長椅、路燈、自行車、路人等）。
   - 讓 8 大目標單字就像世界名畫中的一個個自然元素，而不是「唯 8 存在」。

### 鐵律 2：三層自然景深佈局（前、中、後景均勻散佈）
- **前景（Foreground）**：地面前緣、近景花槽、水池底層、近身物件。
- **中景（Midground）**：核心主體（噴泉池、桌几、拱門通道、立體人物或寵物）。
- **遠景（Background）**：天際線、遠山、高處立面、屋頂煙囪、懸掛氣球。
- **空間分離**：8 個目標必須均勻錯落在左、中、右以及前、中、後景，**判斷框之間必須保留足夠間距，絕對不可相互重疊干擾**。

### 鐵律 3：變異圖（Variant A/B/C）無縫合成與斷層防禦
1. **風格與材質徹底變革**：
   - 變異不是單純換顏色，而是包含材質、紋理、細節造形的徹底轉變（如手繪賀卡轉為火漆封印羊皮卡、普通氣球轉為燙金立體氣球、絡腮鬍男主廚轉為金髮女主廚）。
2. **消滅斷層與框外殘影（最關鍵實戰經驗）**：
   - **變異圖的物件本體必須「完整變異」，絕不能只在判定框內變！**
   - 嚴禁出現「判定框外露出原圖粉紅底色、判定框內卻是金色」的斷層現象。
3. **Method A 局部裁切蒙版合成技術**：
   - 使用 Node.js + Sharp，以 Base 圖作為像素級錨點。
   - 利用帶羽化（feathering）的蒙版將變異物件與原圖邊界完美融合，避免全局重繪導致的畫面抖動。

### 鐵律 4：判定框（Bounding Box / Ellipse / Slot）包覆準則
- **舒適寬裕，包覆完整**：
  - 判定框必須完整罩住目標物件的「所有輪廓」（包含氣球右側凸緣、下方絲帶、禮物頂部的立體蝴蝶結、小狗尾巴與四肢、花束伸出的葉片與花苞）。
  - **寧可稍微留有餘量，也絕不可削邊或切到物件**。
- **雙規格相容參數**：
  ```javascript
  {
    word: 'heart',
    wordZh: '愛心',
    x: 190,           // 橢圓中心 X
    y: 243,           // 橢圓中心 Y
    radius: 142,      // 觸控容錯半徑
    radiusX: 110,     // 橫向半長軸
    radiusY: 142,     // 縱向半長軸
    rotate: 10,       // 傾斜旋轉角
    slot: {           // 矩形合成與裁切槽位 (預留 5~15% 邊界)
      x: 80,
      y: 101,
      w: 220,
      h: 284,
      rx: 16
    }
  }
  ```

### 鐵律 5：先文字討論拍板，後調用生圖工具（最省 Token 策略）
- **嚴禁一上來就盲目出圖**：
  1. 第一步：先討論場景構想、確認 8 大單字清單。
  2. 第二步：擬定 Base 圖構圖 prompt 與三層景深分佈。
  3. 第三步：雙方確認滿意後，才由 Agent 調用 `image-generator` 出圖。
  4. 第四步：審視 Base 圖與判定框，通過後再接續產出變異 A/B/C。

### 鐵律 6：8 取 5 動態出題架構與變異 ABC 補丁鐵則（【生死攸關】嚴禁整張重畫變異圖！）
> [!CAUTION]
> **【絕對禁止行為】**：變異圖（Variant A / B / C）**絕對不是重新繪製一張全新的全景圖**！
> 上次 Book 2 Scene 2 曾發生前一位助理要求生圖模型「畫一張新的 Pier 39 變異 A 全景圖」，導致背景（橋樑、海獅、海水、天色、建築）全部位移重繪，背景差異度高達 95.8%，徹底摧毀了動態 8 取 5 遊戲機制並浪費了大量 Token！**後續接手的任何 AI 助理絕不可再犯此致命錯誤！**

1. **底層遊戲引擎出題邏輯（8-choose-5 Dynamic Slot Engine）**：
   - **單一真理底圖**：遊戲畫面的**左圖**與**右圖**，在底層渲染時使用的是**同一張 100% 相同的 `baseImage`**！
   - **8 取 5 隨機相異機制（`generateSpotterRound`）**：
     - 每一小局開始時，系統從該圖的 8 個單字中，隨機挑選 5 個作為「相異目標」（共有 $C(8, 5) = 56$ 種挑法）。
     - 這 5 個被選中的單字，各自隨機挑選一種變異型態（Variant A、Variant B 或 Variant C，共有 $3^5 = 243$ 種型態組合）。
     - 單一場景總共可產生 $56 \times 243 = 13,608$ 種千變萬化的題目，讓學生每次遊玩都有新鮮感！
   - **右圖補丁覆蓋（Slot Patch Overlay）**：
     - 在右圖的畫布上，**僅針對被選中的 5 個單字**，在其精確的 Slot 矩形槽位（`slot: { x, y, w, h }`）覆蓋帶羽化邊緣的**透明 PNG 補丁圖檔**（例如 `cook_variantA.png`）。
     - **未被選中的另外 3 個單字**：右圖**完全不覆蓋任何補丁**，直接透出底層的 `baseImage`！
     - **結果**：學生在螢幕上看到的，未選中的 3 個單字在左右兩圖**100% 完全相同、像素級一模一樣**；只有被選中的 5 個單字左右相異！
2. **正確的變異出圖與補丁製作流程（參考第 5、6、7、8 冊標準做法）**：
   - **步驟 1（底圖鎖定）**：Base 圖一經審核通過，即作為所有變異的唯一物理坐標與背景基準。
   - **步驟 2（局部變異物件）**：只針對 8 個目標物件設計變異型態（不同顏色、造型、角色或接近等大的物件），物件必須保持在相同的透視與 Slot 槽位內。
   - **步驟 3（產出 24 個透明羽化補丁）**：每個目標產出 3 款變異透明 PNG（共 $8 \times 3 = 24$ 個檔案），存放在 `public/assets/spotter/patches/b{冊}_s{景}/`。補丁邊緣必須具有 12~16px 的平滑羽化 Alpha 漸變，確保無縫融入底圖。
   - **步驟 4（Sharp 合成純淨 Diff 圖）**：工作台與靜態預覽所需的 `diff.jpg`（全 A 版）、`diff_varb.jpg`（全 B 版）、`diff_varc.jpg`（全 C 版），一律由 Node.js + Sharp 腳本**以 Base 圖為底板，將該版本的 8 個羽化透明補丁貼合上去**輸出。如此產生的 Diff 圖，其非目標區域的背景與 Base 圖**100% 像素完全相同（全圖差異度嚴格控制在 15%~20% 之間）**。
